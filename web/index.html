Часть 1. Данные и сопоставление

В обработанной таблице сохранены исходные значения и номера строк. Рядом находятся очищенные поля, идентификатор книги, связь с дублем и пояснения. Листы "Книги", "Дубли" и "Спорные" позволяют отдельно разобрать каждый тип результата.

Правила обработки

  • Убираем лишние пробелы и знаки по краям. Псевдоним в скобках выносим отдельно.
  • Для сравнения названия приводим к одному регистру, приравниваем ё к е, убираем пробелы и пунктуацию. Номера томов сохраняем.
  • Порядок слов в имени автора не важен. Инициалы сохраняем: А. Иванов и Б. Иванов не объединяются.
  • Ключ книги зависит от нормализованных автора и названия. Повторная обработка с новыми строками сохраняет идентификаторы неизменённых книг.
  • Дубль определяется по книге и ключу страницы. Нумерованные зеркала форумов считаются одной страницей по принятому для этих данных правилу. Это предположение нужно проверить при подключении новых сайтов.

Что требует проверки человеком

Одинаковые названия у разных авторов, несовпадение номера тома, ссылки на сборники и страницы автора, аудио при указанном типе ebook. На листе "Спорные" для каждой записи указано, каких данных не хватает: ID книги или ISBN, варианты имени автора, номер тома, состав сборника либо права на формат.

Для спорных записей можно включить рекомендации ИИ через API429. Модель разбирает до 40 спорных строк за загрузку, предлагает, что проверить и каких данных не хватает. Рекомендации попадают на отдельный лист Excel и не меняют исходные значения, идентификаторы и объединение книг.

Часть 2. Проверка страниц

На входе список URL. На выходе статус страницы, извлечённые данные, совпадение с каталогом, статус 0/1/2 и причина решения. Результат доступен в интерфейсе, JSON и CSV.

1 Найдено совпадение и признаки размещения0 Не подтверждено совпадение или размещение не подтверждено2 Проверить автоматического решения нет

Отдельного эталонного каталога в файлах нет. Для прототипа каталог собран из авторов и названий двух листов: 101 книга. Это явное допущение; ошибки исходных метаданных могут влиять на сопоставление.

С HTML извлекаются заголовки, текст и признаки скачивания, чтения, аудио и торрентов. У PDF проверяются метаданные и первые страницы. Название и автор сопоставляются с каталогом; несколько кандидатов требуют ручной проверки. Короткий PDF тоже может быть самостоятельной книгой.

Для известных зеркал Библибобы при пустом ответе запускается браузер Playwright с JavaScript. Если содержимое не получено, сохраняется статус 2. 403 и ошибки сервера также получают статус 2. Удалённая страница получает 0. Упоминание Литрес само по себе не доказывает отсутствие размещения. Если признаки противоречат друг другу, решение передаётся человеку.

ИИ для спорных страниц

В этом задании подключён API искусственного интеллекта API429, модель GLM 5.3 Flash с резервной Qwen 3.8 Flash. Если правила не смогли принять решение по доступной странице, модель дополнительно сравнивает её текст и ссылки с кандидатами из каталога.

Ответ ИИ содержит причину и дословные цитаты. Код проверяет наличие цитат в переданных данных и идентификатор книги. В результатах видны исходное решение правил и результат ИИ. При недостаточных данных или ошибке API сохраняется статус для ручной проверки. На один список допускается до четырёх ИИ-разборов.

Статус 1 означает признаки размещения, а не вывод о нарушении авторских прав. Полнота книги и законность публикации автоматически не устанавливаются.

Как проверяется качество

Проверяем извлечённые данные, выбранную книгу и статус на 20 контрольных сценариях с заранее заданными ответами: совпадение, другой автор, другой том, имя в рекомендациях, транслитерация, сборник, магазин и ошибки сайта. Все 20 сценариев проходят, включая PDF и ошибку доступа с кодом 200. Отдельные проверки контролируют исходные значения Excel и ответы ИИ. Эти сценарии проверяют конкретные ошибки и не заменяют оценку на большой размеченной выборке.

Часть 3. Миллион ссылок

Автоматизация. Очередь с удалением дублей, ограничением параллельных запросов на домен и повторными попытками с паузой. Хранить дату проверки, конечный URL, извлечённые признаки и версию правил. Планировать повторные обходы по частоте изменений. Каталог индексировать по автору и словам названия, затем сравнивать страницу только с кандидатами. Браузер подключать выборочно для страниц на JavaScript.

Участие человека. Неоднозначные совпадения, сборники, псевдонимы и новые шаблоны сайтов. Решения о правах и жалобах оставлять специалисту. Подтверждённые исправления добавлять в каталог и тестовую выборку.

Качество. Размеченная выборка по доменам и типам контента, проверка после изменения правил и выборочная ручная проверка статусов 0 и 1. Резкое изменение доли ошибок или совпадений на домене служит сигналом проверить вёрстку.

Ошибки и метрики. Учитывать 429, капчи, таймауты, редиректы, смену структуры, большие файлы и совпадающие названия. Измерять успешность загрузок, точность и полноту сопоставления, долю статуса 2, задержку обработки, стоимость тысячи URL и размер очереди ручной проверки. При блокировках снижать частоту и проверять условия доступа.

Почему Python

Задание допускает Python, n8n, Make и другие инструменты, но не требует конкретного.

Для интерфейса использованы FastAPI, HTML, CSS и JavaScript без сборки. n8n уместен как внешний планировщик: получить новые ссылки, вызвать проверку, записать результат и направить спорные случаи специалисту. Для самого прототипа дополнительный слой не нужен.
