# Мониторинг книг

Тестовое задание на позицию специалиста по интернет-мониторингу, парсингу и автоматизации.

Есть каталог книг правообладателя и список страниц в интернете. Нужно привести таблицу ссылок в порядок, найти дубли и спорные строки, а потом автоматически проверить страницы: относится ли страница к книге из каталога и есть ли на ней признаки размещения книги.

Рабочая версия: https://test-rboyarskiy.tw1.su (вход по логину и паролю, они переданы вместе с заданием)

- [Пояснительная записка](https://test-rboyarskiy.tw1.su/): правила, результаты, масштабирование
- [Проверка ссылок](https://test-rboyarskiy.tw1.su/check): вставить список URL и получить таблицу, JSON или CSV
- [Обработка таблицы](https://test-rboyarskiy.tw1.su/table): загрузить свою версию таблицы, например с новыми строками, и получить обработанную
- [Таблица результата](https://test-rboyarskiy.tw1.su/files/result.xlsx)

## Что внутри

| Файл | Что делает |
|---|---|
| `normalize.py` | Часть 1. Чистит автора и название, строит ключи для сравнения, находит дубли и спорные строки, собирает xlsx с листами "Как читать", "Строки", "Книги", "Дубли", "Спорные" и "Задание 2". |
| `checker.py` | Часть 2. Загружает страницу, достаёт заголовок, текст, ссылки и кнопки (для PDF метаданные и первые страницы), ищет книгу из каталога и ставит статус 0, 1 или 2 с причиной. На выходе по каждому URL: статус страницы, извлечённые данные, совпадение с каталогом, статус и причина. |
| `app.py` | Веб-страницы и API: `POST /api/check` (список URL, ответ JSON), `POST /api/table` (xlsx, ответ обработанный xlsx). |
| `test_rules.py` | Проверка правил на примерах из задания. |
| `input/` | Исходная таблица из задания. |
| `web/` | Записка, страница проверки ссылок и страница обработки таблицы. |

Статусы:

- `1` книга и автор найдены на странице, есть признаки размещения (файлы, читалка, торрент, аудио, файлообменники);
- `0` совпадение или размещение не подтверждено: книги из каталога на странице нет, страница удалена, или всё ведёт на покупку в Литрес;
- `2` автоматически определить не удалось: сайт не отдал страницу без браузера, ответил ошибкой, или название совпало, а автора на странице нет.

## Запуск

Нужен Python 3.12.

```
pip install -r requirements.txt
python -m playwright install --with-deps chromium
python checker.py "input/Ссылки для тестовых заданий.xlsx" --all out/pages.json
python normalize.py "input/Ссылки для тестовых заданий.xlsx" out/result.xlsx out/pages.json
python test_rules.py
uvicorn app:app
```

После установки зависимостей и браузера выполняются проверка ссылок, сборка таблицы и проверка правил. Последняя команда запускает сервис на http://127.0.0.1:8000.

Проверить свой список адресов из консоли:

```
python checker.py "input/Ссылки для тестовых заданий.xlsx" urls.txt out/check.json
```

В Docker:

```
docker build -t books-monitoring .
docker run -p 8000:8000 books-monitoring
```

## Проверка изменений

`python test_rules.py` проверяет правила сопоставления, неоднозначность, инициалы и запрет внутренних адресов.
`pip install httpx` и `python test_uploads.py` проверяют загрузку XLSX, ограничения файлов и сохранение исходных значений.

Сохранённые результаты имеют дату проверки. Обзор читает `out/part2.json`, который создаётся вместе с полным прогоном `--all`.
В форме проверки результаты появляются по мере готовности через `POST /api/check?stream=true`. Видны число готовых ссылок и оставшиеся сайты. Обычный `/api/check` по-прежнему возвращает список JSON. Ожидание дополнительной страницы скачивания ограничено восемью секундами. При обрыве связи готовые строки остаются в интерфейсе и доступны для скачивания. `python test_progress.py` проверяет постепенную выдачу и совместимость API.
Статус 1 говорит о признаках размещения, не о законности публикации или полноте книги. Ссылка на магазин при противоречивых признаках получает статус 2.
При загрузке новой таблицы сохранённые проверки URL используются повторно; новые URL проверяются отдельно в форме проверки ссылок.

## ИИ для спорных страниц

В задании подключён API429, основная модель `glm-5.3-flash`, резервная `qwen-3.8-flash`. Он используется для спорных строк Excel и доступных страниц со статусом 2 после проверки правилами.
Модель получает ограниченный фрагмент текста, ссылки и до 8 кандидатов из каталога. Она не открывает страницы самостоятельно.
Ответ проверяется: книга должна существовать в кандидатах, цитаты должны быть в переданных данных; для статуса 1 дополнительно сверяются название и автор.
Доверие модели не является измеренной точностью. Без уверенного проверяемого ответа сохраняется исходное решение.

Ключ передаётся серверу через `API429_KEY`, модель через `API429_MODEL`. В репозитории ключей нет.
Настройка сервера хранится отдельно от проекта, контейнер получает её через `--env-file /etc/books-monitoring.env`.
Без ключа работают обычные правила. Ошибка API не останавливает проверку списка.
Лимиты: до 4 ИИ-разборов страниц на список, до 40 запросов за час работы процесса. До 900 выходных токенов для страницы и до 2000 для пакета строк Excel.
Поле `ai` показывает, использовалась ли модель и принят ли её ответ; `rules_status` и `rules_reason` сохраняют исходное решение.
Тесты без платных запросов: `python test_ai_review.py`.

Для обработки данных на `/table` доступна опция рекомендаций ИИ. До 40 спорных строк обрабатываются пакетами по 8, не более двух запросов одновременно. В исходном файле 37 спорных строк, все попадают в разбор. Результат на листе "Рекомендации ИИ", без изменения исходных данных и объединения книг. Цитата и номер строки проверяются кодом. Остальные строки больших файлов получают рекомендации по правилам с явной отметкой источника.
Это один дополнительный запрос на загрузку, до 2000 выходных токенов; общий лимит 40 запросов в час включает оба режима.

Ошибка загрузки фрагмента не принимается как подтверждение отсутствия размещения. Для решения 0 по совпавшей книге нужна явная цитата о покупке, ознакомительном фрагменте или удалении.

## Контроль качества парсинга

`python test_quality.py` проверяет 17 сценариев HTML и 3 сценария PDF с заранее заданными ответами. Включены корректная книга, другой автор, похожие разные имена, другой том, имя только в рекомендациях, автор в микроразметке, автор публикации admin, сборник, магазин и ошибки доступа. Проверяются одновременно статус и выбранная книга.
Это воспроизводимая проверка конкретных ошибок, а не оценка точности на всём интернете.
Скачивание готовой таблицы и результата загруженного файла находится в разделе `/table`, рядом с загрузкой. Эти файлы подписаны отдельно.

## Загрузка страниц и резервные рекомендации

К одному домену и его нумерованным зеркалам запросы идут с интервалом 2-2,5 секунды. При 429, 502, 503 и 504 выполняются ограниченные повторы с паузой; Retry-After учитывается, в том числе в формате даты. Если сервер просит ждать дольше бюджета проверки, ответ остаётся ошибкой, запрос раньше времени не повторяется. Капчи автоматически не решаются.
Некорректный совет ИИ не отбрасывает остальные проверенные советы. Для пропущенных строк, таймаута и недоступного API формируются рекомендации по правилам, с отдельной колонкой источника. На пакет строк даётся до 35 секунд с учётом резервной модели.

При проверке 21 октября 2026 года GLM 5.3 Flash дала 8 проверяемых рекомендаций из 8 за 11,5 секунды. Qwen дала 5 из 8. Gemini вернули перегрузку, MiniMax и DeepSeek превысили ожидание. Это результаты конкретных запросов, а не гарантия доступности. При ошибке основной модели используется резервная в пределах общего срока ожидания.

Для yaa.bibliboba.org и biblo.iboba.club добавлен браузерный повтор Playwright. Он выполняет JavaScript; прочие домены и внутренние адреса заблокированы, DNS закреплён на проверенных публичных IP. За один раз работает один браузер. Сложная антибот-проверка может отклонить и браузер.
